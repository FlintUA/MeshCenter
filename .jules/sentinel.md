## 2026-10-24 - System Log Input Sanitization and Log Injection Prevention
**Vulnerability:** `log_system_event()` accepted un-sanitized string/object inputs for `title`, `source`, and `details`, allowing newline (`\n`, `\r`), NUL (`\x00`), and other control characters to be persisted into `system_events.jsonl`. Unescaped newline characters in log values could corrupt the JSON-lines format or forge log entries (log injection).
**Learning:** `json.dumps()` escapes control characters in string values when producing JSON, but direct or raw field formatting prior to JSON serialization or downstream log parsing can lead to log corruption or unexpected display behaviors when control characters are present. Sanitizing control characters (`ord(c) < 32` or `127`) to spaces before logging ensures clean single-line text data across system event fields.
**Prevention:** Use a central string sanitization helper for system logging that converts inputs to strings, strips/replaces control characters with spaces, and enforces maximum length bounds on fields.
