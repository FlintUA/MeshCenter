# MeshCenter v1.12.1

Range: `v1.12.0..main`, PRs #363 (UI1), #364 (DOC1) and #366 (UPD1).

**This release can be applied from the Updates card.** `requirements.txt`, `adapters/meshtastic/requirements.txt`, `install.sh`, `meshcenter-firstboot.sh`, the systemd unit, the sudoers files, `gunicorn.conf.py`, `wsgi.py` and the Dockerfile are unchanged since v1.12.0, so no package install or manual step is needed. Open **Workspace → System → Updates**, press **Check now**, then **Update** - with the caveat below. As with any update, keep a copy of `data/` and `config.py`. Docker users rebuild the image (`meshcenter:1.12.1`).

## Updater: installs exactly the release tag, with rollback (UPD1, #366)

- **The update goes to the release's tag, never to `origin/main`.** Until now the card advertised a release but merged whatever `origin/main` was, and a node sitting on a detached `git checkout vX.Y.Z` could not update at all ("no upstream"). Now the target is the latest GitHub release (non-draft, non-prerelease); only that tag is fetched. It works from branch `main` (fast-forward to the tag's commit) and from a detached HEAD (re-detached at the tag).
- **Safe by construction.** It refuses, with a plain reason and nothing touched: a dirty working tree, local commits that diverge from the release, any branch other than `main` ("On branch X - update manually (git)"), a tag that cannot be fetched, and a checkout that already contains the release. **It never offers or performs a downgrade** - the old string comparison offered one to any node newer than the published release; the check is now numeric. A release that changes `requirements.txt` is still not applied; the card shows the manual steps.
- **One-click Roll back.** After a successful update the card shows **Last update: 1.12.0 → 1.12.1**, a **Roll back** button (a red confirmation naming both versions) and the equivalent manual command. Rolling back returns to exactly the commit recorded before the update, once; it is blocked, with the manual command, if the dependency files differ.
- **The System Log tells the story** (source `update`): Update started, Update restart, Update finished or Update failed (the new process checks that the version it runs is the one that was applied), and the same for rollbacks and refusals.
- **No more false errors on restarts.** `systemctl restart` kills the process that issues it, so every update, **Restart MeshCenter** and radio-profile switch used to log a false ERROR ("Restart after update failed … died with SIGTERM") and briefly show "Listener down" with an "unexpected exit". Every planned restart (update, rollback, Restart MeshCenter, reboot/shutdown, profile switch) now opens a 60-second window in which the helper's SIGTERM is INFO, the listener exit is intentional and the radio status reads "MeshCenter is restarting". A restart that really fails is still an ERROR.

## In-app dialogs instead of browser pop-ups (UI1, #363)

- Every native `confirm()`, `alert()` and `prompt()` is gone (41 of them), replaced by one themed dialog (light/dark, phone width, Enter/Esc, focus trap) - red confirm button for destructive actions (delete, restart, reboot, shutdown, update, forget Wi-Fi, remove connection). Failures that used to be a pop-up (saving settings, chat actions) are error toasts that stay at least 10 seconds and can be dismissed; export date errors appear under the fields.
- **Behaviour changes to know about:**
  - Editing a TCP radio connection is **one dialog with Host and Port**, checked as you confirm: an **invalid port is now refused with a message** instead of silently becoming 4403.
  - **Media "Delete all" is one dialog** that says how many images it will delete (the second "are you sure?" is gone).
- A test now fails the build if a native dialog is ever added again.

## Docs (DOC1, #364)

- The Docker guide (`docs/Docker_Installation.md`) is linked from README, INSTALL.md and the User Guide, and brought up to date: accepted on a Synology DS920+ with a real T-Beam, a step-by-step walkthrough for first-time Docker users with a complete compose file, Release radio (it survives a NAS reboot), the one-TCP-client rule, delivery confirmations over TCP, and corrected numbers (reconnect backoff caps at 2 minutes). The earlier claim that the T-Beam closes sessions by itself was wrong - repeated quick drops almost always mean another client is using the radio.
- README: "Can I run MeshCenter without a Raspberry Pi?" (Debian/Ubuntu natively, or Docker on x86-64 with a TCP radio).

## Upgrade notes

- **The update *to* 1.12.1 is still done by the old updater** (the one in 1.12.0 and earlier), because the new one arrives with this release. That works from the Updates card on a node that is on branch `main`. A node on a detached `git checkout v1.12.0` (the card reports "no upstream") needs `git fetch --tags && git checkout v1.12.1` and `sudo systemctl restart meshcenter.service` once. **From 1.12.1 on the card installs exactly the release tag**, from `main` or from a detached checkout.
- Docker: rebuild with `deploy/docker/build.sh` (or the plain `docker build` command in the guide) from the `v1.12.1` tag; the image is still not published.

## Known issues

- Unchanged from v1.12.0 (see its notes and `KNOWN_ISSUES.md`): Bluetooth is send-only; no remote waypoint deletion over TCP; message times use a fixed 24-hour format (KI-007).
- Docker image labels are empty (the tag and the footer are the version source); OCI labels are planned.
