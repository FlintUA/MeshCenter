# MeshCenter v1.12.2

Range: `v1.12.1..main`, PRs #367 (README Docker mentions), #368 (DASH1) and the v1.12.2 small-items PR.

**This is the first release installed by the tag-based updater.** From the Updates card on v1.12.1 the update goes to exactly the `v1.12.2` tag (from branch `main` or a detached checkout), with the new "Last update" line, the Roll back button and the System Log events. `requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py` and `wsgi.py` are unchanged since v1.12.1, so nothing is blocked and no manual step is needed. Open **Workspace → System → Updates**, press **Check now**, then **Update**. As with any update, keep a copy of `data/` and `config.py`. Docker users rebuild the image (`meshcenter:1.12.2`).

## Updates: host-file changes ask for a manual step instead of being missed

- An update never installs the systemd unit, the sudoers templates, the udev rule or the two privileged helper scripts (that is how `INSTALL.md` has always described it), so a release that changed one of them used to say nothing. **Such a change is still not a block** (only dependency files block an update), but the update now reports it: the card shows **"Manual step needed after this update"** with the exact command for each changed file (the same commands `install.sh` runs; the sudoers files are rendered and checked with `visudo` before they replace the live file), each with a Copy button, and the System Log's "Update started" and "Update finished" entries name the files.
- Files watched: `deploy/meshcenter.service`, `deploy/meshcenter.sudoers`, `deploy/meshcenter-wifi.sudoers`, `deploy/meshcenter-hw.sudoers`, `deploy/99-meshcenter-rtc.rules`, `scripts/meshcenter-network-helper`, `scripts/meshcenter-hw-config`. The container files under `deploy/docker/` are not host files and never trigger it. A rollback reports the reverse changes the same way.

## Node Manager: a released radio reads "Released"

- The profile card's connection badge showed "Offline" in the warning colour for a radio you had released on purpose. It now reads **Released** in the same neutral style as the status line, for serial and TCP radios, in all four languages.

## Docker image: OCI labels

- The image now carries `org.opencontainers.image.version` (the `MESHCENTER_VERSION` build argument), `.revision` (the exact git commit), `.source`, `.title` and `.licenses` (`MIT AND GPL-3.0-only`), readable with `docker image inspect meshcenter:1.12.2 --format '{{json .Config.Labels}}'`. `deploy/docker/build.sh` and the compose file pass the revision (a build from a modified tree is marked `-dirty`); with a plain `docker build` add `--build-arg MESHCENTER_REVISION=$(git rev-parse HEAD)`. The image is still not published.

## Text and docs

- **Plain hyphens everywhere (DASH1, #368).** No em dash or en dash remains in the interface (all four languages), server and installer messages, docs, release notes or code comments; the empty-value placeholder in the UI is now `-`. A CI check (`scripts/check_no_long_dashes.py`) keeps it that way, and `CLAUDE.md` documents the rule.
- **README (#367):** Docker server mode is mentioned next to every "runs on Raspberry Pi" statement (tagline, feature strip, a Docker badge, Overview, Why, Features, Radio connection, Tested Hardware, FAQ and "Reporting Issues").
- `docs/Docker_Installation.md` examples now use 1.12.2 and describe the image labels.

## Upgrade notes

- **Updates card works** from v1.12.1 (the first update performed by the tag-based updater). A node still on v1.12.0 or older updates to v1.12.2 with the old updater; follow the v1.12.1 notes for that.
- Docker: rebuild with `deploy/docker/build.sh` from the `v1.12.2` tag; the image is not published.

## Known issues

- The "Manual step needed" notice stays on the card until the next update or rollback; there is no "done" button yet.
- Unchanged from v1.12.1: Bluetooth is send-only, no remote waypoint deletion over TCP, message times use a fixed 24-hour format (KI-007).
