# MeshCenter v1.12.3

Range: `v1.12.2..main`, PRs #371 (SIG1) and #372 (SIG2).

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py` and `wsgi.py` are unchanged since v1.12.2, so nothing is blocked and no manual step is needed. Open **Workspace → System → Updates**, press **Check now**, then **Update** (or **Roll back** to v1.12.2 afterwards if you want to). As with any update, keep a copy of `data/` and `config.py`. Docker users rebuild the image (`meshcenter:1.12.3`).

## Security: a received text could forge the sender and radio metrics (serial)

- On a serial radio the `--listen` line was parsed with regular expressions over the whole line, text included. A message whose text contained something like `'fromId': '!deadbeef'`, `'rxSnr'`, `'id'` or `'channel'` could therefore make MeshCenter show a different sender, chat, packet id or signal values than the packet really carried. The sender, channel, packet id and radio metrics are now read from the line with the text and the payload blanked out, so a message text can no longer influence them. The TCP path was never affected.

## Serial text is now identical to TCP

- The CLI prints a received packet as a Python dict, so a serial text arrived in escaped form: a real line break became a literal backslash-n, a backslash became two, quotes could be escaped. The text literal is now decoded exactly (one string token, nothing else is ever evaluated; malformed input falls back to the raw text and logs once, never the message). Serial stores byte for byte what TCP stores for the same packet: real line breaks, single backslashes, quotes, emoji, Cyrillic. Whitespace is no longer trimmed, like TCP. Reply quotes and MCAttach frames get the real text.
- Messages stored before the update keep their old form (no history rewrite). The display converts a literal backslash-n into a line break, so they stay readable; a user-typed literal backslash-n can still show as a break.

## Reply with signal

- A new **Reply with signal** item in the message menu replies natively to a received message with its SNR, RSSI and hop count (plain ASCII, no names, language-neutral). It is hidden for your own and system messages and for messages without signal data, and disabled while the radio is released.
- Every received text now keeps its own radio metrics (SNR, RSSI, hop start and limit), serial and TCP alike. **Only messages received after the update carry them**; older messages have no signal data, so the item does not appear for them.
- Message bubbles keep line breaks, and one-line previews join lines with " · ".

## Updates

- After a tag update the new process refreshes the `origin/main` reference in the background, so `git status` no longer reports a cosmetic "ahead N" on a node that is exactly on a release.

## Upgrade notes

- **Updates card works** from v1.12.2 and v1.12.1.
- Docker: rebuild with `deploy/docker/build.sh` from the `v1.12.3` tag; the image is not published.

## Known issues

- Waypoint names and descriptions and NodeInfo names received over serial still arrive in escaped form (SIG3, the same decoding is planned).
- Unchanged from v1.12.2: Bluetooth is send-only, no remote waypoint deletion over TCP, message times use a fixed 24-hour format (KI-007), and the "Manual step needed" notice has no "done" button.
