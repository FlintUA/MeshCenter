# MeshCenter v1.13.0

Range: `v1.12.3..main`, PRs #375 to #384 (CAM2 network cameras, CAM2-M, CSRF1, MOB1).

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py`, `wsgi.py`, `install.sh` and `meshcenter-firstboot.sh` are unchanged since v1.12.3, so nothing is blocked and no manual step is needed. Open **Workspace → System → Updates**, press **Check now**, then **Update** (or **Roll back** to v1.12.3 afterwards if you want to). As with any update, keep a copy of `data/` and `config.py`: for saved network cameras `data/camera_secrets.json` holds the camera passwords (a plain owner-only file, not encrypted), so keep backups where only you can read them. Docker users rebuild the image (`meshcenter:1.13.0`); see **Upgrade notes** for ffmpeg.

## Network cameras (RTSP)

- **Devices → Network cameras**: add a camera that speaks RTSP (name, address, port, user name, password, sub and main stream paths, TCP or UDP). Several cameras can be saved; the Camera tab has a source selector. Only addresses on your own network are accepted (private, link-local; never loopback, this machine, cloud metadata or public addresses; in Docker also not the container's own networks). Never forward a camera's ports to the Internet.
- **Live view without conversion**: one ffmpeg per camera copies the camera's H.264 into the browser (MediaSource / ManagedMediaSource), so a Raspberry Pi Zero 2 W shows the sub stream with a few percent of one core (measured on a Pi Zero 2 W class node: about 1 to 8 percent, 47 MB). The 4K main stream also plays without a transcode when the link is fast enough. H.265 is detected and explained instead of showing a black box. Sub stream is the default; the main stream needs a fast link (not Wi-Fi at a weak signal).
- **Reconnect**: a lost camera or network is retried with growing delays (2 s up to 60 s), never in a fast loop; a wrong password, a wrong path, H.265 or a blocked address stop retrying until you edit the source or press Reconnect (repeated wrong logins can lock a camera account). Up to 4 viewers per camera and 6 in total; the fifth gets a clear message. A stream ends after 10 minutes and the player reconnects, so a logged-out browser cannot keep a stream open for longer (the reconnect is a second of interruption). The first picture can take several seconds on a Pi (it waits for the camera's next keyframe; a shorter keyframe interval in the camera's own settings makes it faster); reopening within a minute is instant.
- **Secrets**: the password is write-only (the API says only "set"), is never in `ps` output, logs, the System Log or API answers, and is stored in `data/camera_secrets.json` (mode 0600, not encrypted).
- **ffmpeg is required** (it is an external program, not a Python package). See **Upgrade notes**.

## Reolink camera control (optional)

- In a camera's form set **Control** to **Reolink API** (same user name and password). **Check control** logs in, reads what the camera offers (snapshots, zoom with its range, focus position) and saves the result. Verified against a Reolink RLC-811A (login, abilities, zoom 0 to 28, focus 0 to 238, sub and full snapshots); the client is written from the documented protocol, uses only the standard library and works only with what the camera reports.
- **Certificates**: verified by default. A camera with a self-signed certificate is trusted only after you confirm its SHA-256 fingerprint; the handshake is compared with that pin before any password is sent, and a changed certificate asks you again. Plain HTTP needs an explicit tick-box with a warning.
- **Lens zoom** (Camera tab → **Lens**, only when the camera reports zoom): read when the tab opens and after each move, never polled; the slider is locked while the lens moves, quick drags coalesce (the latest target wins), and the position is read back from the camera. Focus is shown read only (the camera's autofocus follows zoom). A view-only account cannot move the lens and the tab says which right is missing. Zoom is the only thing MeshCenter ever writes to a camera.
- **Pictures into Media**: **Take picture** saves the camera's own full-resolution picture (or the small one, per camera), at most one every two seconds, with the source and time in a metadata file next to it; a camera without the API gives one frame of the running preview instead (start the preview first). A full disk is reported, never half a file.
- If the camera's web API is unreachable the live view keeps working.

## Phones

- **Phone layout** (screens up to 768 px wide): one page at a time instead of three squeezed columns. The workspace is the default; the dock buttons open the Base and Nodes panels as full-screen pages; the tabs scroll sideways with 44 px touch targets; the camera card wraps; the dock is one row of real buttons. Desktop layout is unchanged.
- **Android Chrome** plays the network camera. **Safari on an iPhone before iOS 17.1** has no MediaSource at all: it now says so at once ("this browser cannot play the camera stream") instead of waiting forever. With Reolink control it shows the camera's own picture about once a second instead ("Snapshot mode"). Verified on an iPhone SE with iOS 15.
- `?camdiag=1` on the page address shows a copyable diagnostics panel for the Camera tab (browser capabilities and playback attempts; no address, URL or password in the text).

## Small fixes

- The camera source card shows the real error code (and a translated message for an expired security token) instead of "could not be saved", and logs the failed request to the console.
- `csrf.js` is now the first script of the page, so no request can run before the token wrapper exists.
- A "too many viewers" message no longer turns back into "connecting".

## Upgrade notes

- **Updates card works** from v1.12.3, v1.12.2 and v1.12.1; no manual step.
- **Native installs need ffmpeg for network cameras.** Installs made with the current `install.sh` or the first-boot script already have it (they have installed `ffmpeg` and `v4l-utils` for USB cameras since v1.9.0). On an older install run `sudo apt install ffmpeg` (add `v4l-utils` for USB cameras) and restart the service; until then Devices → Network cameras says "ffmpeg is not installed on this device". The updater cannot install system packages and only watches repository files, so it does not mention ffmpeg by itself.
- **Docker: the image does not include ffmpeg yet.** Network cameras can be saved but not shown ("ffmpeg is not available in this Docker image yet"). Adding Debian's ffmpeg would grow the image from about 193 MB to about 818 MB, so a small purpose-built ffmpeg is planned instead. CSI and USB cameras do not work in the container either (unchanged). Rebuild with `deploy/docker/build.sh` from the `v1.13.0` tag; the image is not published.

## Known issues

- Docker: no network camera picture until the image gets ffmpeg (above).
- Safari before iOS 17.1 shows a picture only about once a second and only for cameras with the Reolink API; other cameras get the "cannot play" message there (HLS for old iPhones is not planned).
- On the phone layout only the Camera, Chats, Devices, Media and Files pages were checked; Map, System, Settings, About and Node Manager pages are not adapted yet.
- Logging out cannot close a stream that is already open: it ends within 10 minutes (server-side session revocation is a backlog item).
- The 4K main stream needs a fast link; on weak Wi-Fi use the sub stream. A weak Wi-Fi link can also make the first picture take about 9 seconds.
- Focus cannot be changed from MeshCenter (only read); image settings of a network camera are changed in the camera's own app.
- Unchanged from v1.12.3: Bluetooth is send-only, no remote waypoint deletion over TCP, waypoint and NodeInfo names received over serial still arrive in escaped form (SIG3), message times use a fixed 24-hour format (KI-007).
