# MeshCenter v1.13.11

Range: `v1.13.10..main`, MCA-UX1: file transfers in the chat, a Files tab dot, received-copies storage with an explicit cleanup, and page freshness after an update. The MCA-VAULT proposal (`docs/proposals/MCA-VAULT.md`, docs only) is also in this range; no vault code is shipped.

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py`, `wsgi.py`, `install.sh`, `meshcenter-firstboot.sh` and the Dockerfile are unchanged since v1.13.10, so nothing is blocked and no manual step is needed. There is no database schema change. Stored chat messages gain an optional `mca` field (older code ignores it, so **Roll back** is safe). `templates/index.html` differs from v1.13.10 only in its cache tokens and two new elements (the Files tab dot and the received-copies line). Open **Workspace > System > Updates**, press **Check now**, then **Update** (or **Roll back** to v1.13.10 afterwards). Reload the page once with Ctrl+F5 so the browser takes the new page. Docker users rebuild or load the image (`meshcenter:1.13.11`); the pinned ffmpeg version for this release is 7.1.5, unchanged.

## Chat: file transfers

- **No more raw `MCA1:` text.** The server marks every MCAttach frame when it is stored (`mca`: OFFER, CONTROL, or FILE_SENT). Control frames (acknowledgements, key exchange, cancel) are kept in the history but are never shown, never counted as unread and never the chat list preview. Messages stored before this version are marked when the history is read.
- **One compact bubble per transfer.** An incoming offer shows "File received" with "Open in Files"; a transfer you queue (including a scheduled picture) shows "File sent". A tap opens that transfer in Files.
- **Exact link.** When the MCAttach service turns an offer into a transfer it tells the chat, and the real transfer id is written into that message, so the bubble opens exactly that transfer. Messages from before this version fall back to the received transfer of that contact closest in time (within six hours).

## Files

- **Tab dot.** A colored count on the Files tab (desktop and phone) for transfers that need attention and appeared after you last looked at Files, remembered per device. Polled once a minute, hidden while Files is visible.
- **Selected transfer card** is highlighted like the selected node or chat, in every theme (the dark theme used to paint over it).
- **Summary line** now has a separator between "need attention" and "saved".
- **Received copies.** Files shows how many received copies the node holds in its internal cache and how much room they take. **Delete older received copies...** asks for a number of days, then shows a danger confirmation with the count and size. It never touches files saved with Save to Files, and nothing is ever deleted automatically (new worker command `attachment_purge_received_cache`; the row and its history stay).

## Page freshness

- The page is now sent with `Cache-Control: no-cache`.
- When the server reports another version than the page was rendered with (an update happened while the tab stayed open), a clear "A new version is installed" notice with a **Reload** button appears. Nothing changes silently.
