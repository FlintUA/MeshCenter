# MeshCenter v1.13.4

Range: `v1.13.3..main`, four changes: the phone layout (menus, sizes, chats), and the last relay of a received message with a Trace route to the sender.

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py`, `wsgi.py`, `install.sh` and `meshcenter-firstboot.sh` are unchanged since v1.13.3, so nothing is blocked and no manual step is needed. Open **Workspace → System → Updates**, press **Check now**, then **Update** (or **Roll back** to v1.13.3 afterwards). Reload the page once with Ctrl+F5 so the browser takes the new page. Docker users rebuild the image (`meshcenter:1.13.4`).

## Phone layout (MOB2-A, B, C)

- **The dock menus work on a phone.** Workspace (System, Settings, About), Map layout and the notification centre were clipped to nothing by the dock and could not be opened. They are now bottom sheets with a backdrop (tap outside or Esc closes them), 44 px rows and the page links first.
- **Dock and tabs:** 44 px buttons, readable text, and a fade on the side of the tab row that has more tabs.
- **Chats are two pages:** the list of conversations takes the whole screen (rows at least 56 px); opening a chat shows the conversation with a **Back** button in the header. Nothing changes on a wide screen.
- **Messages:** the per-message actions button is a 44 px target in the bubble corner, and short messages no longer wrap early (a style rule cut every bubble to 85 % of its own width, which broke a sender name mid-word).

## Last relay of a message and Trace route (SIG4)

- Firmware 2.6+ tells each received message only the low byte of the node that relayed it last. MeshCenter keeps it per message and matches it against the nodes it heard **directly** in the last 24 hours (falling back to nodes heard at all in the last 2 hours only if there is none). **Message Info** shows `Relay: name (0x84)`, `possibly: A, B (0x84)` when several nodes share the byte, `probably: X (0xDC)` when only the 2 hour fallback matched, or `unknown`.
- **Reply with signal** adds a `Via <short name>` line only when the relay was resolved from a node heard directly. A guess never goes on air.
- **Trace route to sender** is a new item in the message menu (serial radios only; on a TCP radio it is disabled with the reason). The result opens in a window with the route there and back and the SNR of each hop. The same node can be traced once a minute, enforced by the server too, because every trace uses airtime on the shared mesh.

## Busy chip and the password checkbox (SIG4b)

- While a command holds the radio (traceroute, node scan, sending, a channel read) the header chip reads **Busy: traceroute** (or node scan, radio command) instead of **Offline**.
- Switching password protection off with an empty "Current password" field no longer sends a request: every such request counted as a failed attempt, and a few of them locked the user out. The box now goes back and asks for the password first, and a lock-out message names the seconds.

## Known issues

Unchanged from v1.13.3 (see its notes). The chip says plain **Busy** for about 14 seconds after the listener is back, until the stored health refreshes (planned). The tablet widths (769 to 1100 px), the Nodes, Base and Node Manager pages on a phone, and the small System, Settings and About controls are planned for v1.13.5. Trace route over a TCP radio is not available yet.
