# MeshCenter v1.13.8

Range: `v1.13.7..main`, four changes: live network-camera video in the Docker image (a minimal LGPL ffmpeg built into it), a fix for switching between the camera's sub and main stream, a player that rebuilds itself after a playback error, and a compact Camera Mode panel.

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py`, `wsgi.py`, `install.sh` and `meshcenter-firstboot.sh` are unchanged since v1.13.7, so nothing is blocked and no manual step is needed. Open **Workspace > System > Updates**, press **Check now**, then **Update** (or **Roll back** to v1.13.7 afterwards). Reload the page once with Ctrl+F5 so the browser takes the new page. Docker users rebuild or load the image (`meshcenter:1.13.8`).

## Docker: live video of network cameras

- **A minimal LGPL ffmpeg is built into the image** (Dockerfile stage 1) instead of Debian's package (205 packages, about 625 MB): **ffmpeg 7.1.5**, the latest point release of the 7.1 line, built from the pinned source tarball (URL and sha256 are in the Dockerfile and checked on every build). It has no external libraries and no GPL or nonfree flags, only what the camera code uses (RTSP over TCP or UDP, H.264 copied without re-encoding, the one-shot picture and the MJPEG fallback). The ffmpeg part of the image is 15.9 MiB; the image grew from 357 MB to 387 MB on disk.
- **RTSPS (RTSP over TLS) is not supported yet.** Local USB and CSI cameras are not part of the container image (a container has no camera hardware).
- **Licence:** the image label is now `MIT AND GPL-3.0-only AND LGPL-2.1-or-later`. The exact source tarball, the licence text and the configure line are inside the image under `/usr/share/doc/meshcenter-ffmpeg/`; the full record is in `docs/legal/camera-dependency-review.md` and `THIRD_PARTY_NOTICES.md`. The image is still not published (D0 section 5).
- **Gate:** `scripts/check_docker_ffmpeg.py` (and a CI job) runs the code's real ffmpeg arguments against a fake RTSP camera inside the built image and fails on any GPL flag, a missing library, a broken live stream, picture or MJPEG fallback, or a size over 60 MB.
- **Pinned ffmpeg version for this release: 7.1.5.** A security point release of the 7.1 line means a rebuilt image (`docs/development/RELEASING.md` has the checklist line).

## Camera: switching the stream

- **Fixed:** after switching between the sub and the main stream the player could fall into snapshot mode ("This browser cannot play live video") and stay there until the camera was turned off and on; rarely the same after leaving the Camera tab and coming back. Cause: for a moment after the switch the server still held the old stream's first segment while its stream facts were already cleared, and a viewer connecting in that gap got an empty codec, which the player took for a browser that cannot play video. The server now clears both at once and answers "not ready" until the new codec is known; the player treats that as "ask again".
- **The player rebuilds itself:** snapshot mode now comes only from a real capability check (no MediaSource, a codec the browser rejects, ffmpeg missing). Any playback error (SourceBuffer, MediaSource, video element) rebuilds the player with a fresh MediaSource and a new codec string, one retry at a time with a growing delay, never snapshot mode. A slow first frame (a 4K main stream) is retried twice before the message appears. A 2-second watchdog replays a paused player, jumps a stalled one to the live edge and rebuilds a dead one; coming back to the tab resumes or rebuilds it.
- **Main stream is not touched:** the stream is remuxed with `-c copy`. A real 3840x2160 stream through MeshCenter's exact ffmpeg arguments decodes to the identical frames as its source, and the player reports 3840x2160. The camera's bitrate is set in the camera app; MeshCenter changes no camera setting.

## Camera Mode panel

- **Compact:** one row with **Stream**, **Take picture** and **Picture quality**, and one small muted line under it (what Take picture does and where the image settings are). The facts grid is gone; resolution, frame rate, codec, bitrate and state are in the status line of the tab bar. On a narrow card the labels are hidden (the selects keep their accessible names), the stream choice uses the short labels, and the row wraps cleanly on a phone.
