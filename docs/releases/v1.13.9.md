# MeshCenter v1.13.9

Range: `v1.13.8..main`, seven changes: a rebuilt Media gallery (sort, three views, thumbnails, lightbox, bulk actions, a view remembered per device), a phone layout and long-press selection for it, tap-again-to-refresh on the main tabs, a fix for network-camera pictures saved in the wrong resolution, sending gallery pictures to a contact through MCAttach, a fix for the Send dialog opened from Media, and a CI cache for the Docker ffmpeg source.

`requirements.txt` (Pillow was already required), `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `gunicorn.conf.py`, `wsgi.py`, `install.sh` and `meshcenter-firstboot.sh` are unchanged since v1.13.8, so nothing is blocked and no manual step is needed. There is no database change; `settings.json` gets a new `media` section (older code simply ignores it, so **Roll back** is safe). Open **Workspace > System > Updates**, press **Check now**, then **Update** (or **Roll back** to v1.13.8 afterwards). Reload the page once with Ctrl+F5 so the browser takes the new page. Docker users rebuild or load the image (`meshcenter:1.13.9`).

## Media gallery

- **Sort, views, bulk actions:** sort by newest, oldest, name, size or camera; large, small or list view; select several pictures to download or delete them in one step. The sort is shared by every device, the view is remembered separately for a phone and for a desktop (`media.sort`, `media.view_desktop`, `media.view_mobile`).
- **Thumbnails:** about 480 px thumbnails are made on first request (and by a background backfill) into `screenshots/.thumbs/`, so a gallery of hundreds of pictures no longer loads full images. The thumbnail folder is not counted as pictures.
- **Lightbox:** open a picture full size with previous/next, the picture's details, download and delete.
- **One sticky toolbar** with a normal and a selection state of the same height (no layout jump), compact on a phone. All icons are inline SVG. On a phone the grid shows three small or one large picture per row (two in landscape), list rows are about 56 px.
- **Long press** (about 500 ms) starts selection on a touch screen; scrolling and tapping still work as before. Thumbnail checkboxes are hidden on touch outside selection mode.
- **Camera full screen** button on the camera picture.
- **Honest picture source:** the toast after Take picture says what was really saved (camera's own full or small picture, or a frame of the running stream, and why).

## Network camera pictures

- **Fixed:** Take picture could silently save the running stream's resolution (for example 640x360) instead of the camera's full picture. Cause: the Reolink Snap call sometimes answers with the unclassified code -104 (a stale login token), and the code then fell back to a stream frame without saying so. Now the stale token is logged out first (so repeated retries cannot use up the camera's session limit), a fresh login is made, the Snap is retried once, and a fallback is reported to the user and written into the picture's sidecar (`fallback_reason`).

## Main tabs on a phone

- **Tap the active tab again** to refresh it: Devices, Files and Media reload; Camera reconnects the stream; Chats goes back from a conversation to the list. Not while a dialog, menu or field is open; at most once per 2 s; the active tab shows a small glyph and an `aria-label`. Wide screens are unchanged.
- On a phone the card titles of Files, Camera and Devices are hidden (as in Media). The Add network camera button has normal contrast.

## Sending gallery pictures (MCAttach)

- **Send** in the selection toolbar (up to 10 pictures) and in the lightbox (one picture). The existing Send dialog in a pictures mode: recipient, relay, expiry, comment. A contact without a key can be chosen and shows **Connect securely** (the same key request path, including its auto-retry); Send stays off until the contact is trusted.
- **Resize before sending** is on by default (long edge 1280 px, JPEG quality about 82); other choices are 1920 px and original. The copy is made by `GET /api/camera/screenshot/<file>?send=1280|1920|original`; location and camera data (EXIF/GPS, comments) are removed from every copy; a picture already smaller than the target is not re-encoded. Original works only within the 5 MB MCAttach limit, otherwise a clear message and nothing is uploaded.
- **One transfer per picture** through the existing `POST /api/attachments`, each with its own request id, visible in Files. A full command queue (429) stops the run with a clear message; the toast reads "3 of 3 queued". The receiver accepts each offer as usual.
- **Live-verified** on dev to Flint_Echo: two pictures at 1280 (3840x2160 to 1280x720, 237,767 bytes; a comment segment removed), one original (byte-identical), one from the lightbox, all opened on the receiving node.
- **Fixed before release:** opening this dialog from Media without having visited Files first stayed on "Loading providers" (the Files module ignored loaded data while its own tab was not active). Covered by a test that fails without the fix.

## CI and Docker

- The Docker image's ffmpeg source tarball (pinned **ffmpeg 7.1.5**, same URL and sha256) now has its own build stage; CI caches it by its sha256 and retries the download once, because ffmpeg.org's TLS handshake timed out now and then. The sha256 is checked again in the build stage. A normal `docker build` is unchanged.
- **Pinned ffmpeg version for this release: 7.1.5.**
