# MeshCenter v1.14.0

Range: `v1.13.11..main` (PRs #444 to #456). The headline is the **MCAttach vault**, an optional encryption of everything MCAttach stores on the device. **It is off by default, and nothing changes for an installation that does not turn it on.** The range also brings a searchable recipient picker, a phone layout for Files, one localized way of writing file sizes, a gallery filter, MCAttach polish, and two fixes found while testing the vault on a real node.

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `install.sh`, `meshcenter-firstboot.sh` and the Dockerfile are unchanged since v1.13.11 (PyNaCl was already a dependency), so nothing is blocked and no manual step is needed. `gunicorn.conf.py` gains a `worker_exit` hook; the service restart that the update performs picks it up. There is **no database schema change**. `templates/index.html` differs from v1.13.11 only in its cache tokens, three new script tags (`format-size.js`, `recipient-picker.js`, `vault-ui.js`) and the new elements of the vault and of the Files layout. Open **Workspace > System > Updates**, press **Check now**, then **Update**, and reload the page once with Ctrl+F5.

**Roll back and the vault.** Rolling back to v1.13.11 works as long as the vault was never enabled. **While a vault exists, Roll back is refused** ("Disable the vault first"), because older versions cannot read the encrypted files and could write plain files next to them. Disable the vault in the UI before you go back to an older version, an older Docker image or an older `git checkout`.

Docker users rebuild or load the image (`meshcenter:1.14.0`); the pinned ffmpeg version of this release is 7.1.5, unchanged.

## MCAttach vault (new, optional, off by default)

Guide: [docs/MCAttach_Vault.md](../MCAttach_Vault.md). Design: [ADR-0013](../architecture/ADR-0013-mca-vault.md).

- **What it encrypts:** received and queued files, their names and comments, the MCAttach identity key and the Relay upload tokens, with a passphrase only you know (Argon2id key derivation, libsodium secretstream, and a recovery key). **It does not cover the Media gallery** or any other MeshCenter file.
- **Locked after every start.** While locked, the Files list shows "Locked" instead of names, offers are still recorded, nothing is accepted, downloaded or decrypted, sending is refused (the Send dialog offers Unlock), and a scheduled picture send is skipped with one System Log line (the schedule stays on). A lock chip sits in the bottom bar next to the workspace label.
- **Enable wizard** (Settings > MCAttach vault): notices, passphrase with a strength hint, a plain backup of the current data (on by default), progress, the recovery key shown once with two groups typed back, and an unlock test. **Disable** decrypts everything back; its backup is encrypted and is listed as such.
- **The plain backup warning.** The plain backup made at enable is a complete readable copy of what the vault protects. A red warning stays in Files and on the vault card until you delete it; it cannot be dismissed and is derived from the folder on every read.
- **Roll back is refused while a vault exists** (see above). The Updates card shows the button disabled with the reason.
- **Flash storage.** Deleting plain files on an SD card or eMMC is not a secure erase; enable the vault on a fresh installation for the strongest protection. The enable dialog says so.
- **Docker:** the vault is locked after every container start. An **opt-in**, off-by-default `MESHCENTER_MCA_VAULT_UNLOCK_FILE` (a Docker secret) unlocks a NAS by itself after a restart, with the trade-off written down: the key is then derivable from the volume plus the secret. It is read once per start, ignored outside the container, and every use is noted in the System Log.
- **Memory:** an unlock needs the Argon2id memory limit (64 MiB on a Raspberry Pi Zero 2 W) for about a second and gives it back. Measured on the Zero 2 W, nothing is retained after a derivation (`scripts/vault_memory_probe.py`). The enable dialog warns about disk swap.
- **Verified on a real node** (a Zero 2 W): enable in about 4 seconds on a small workspace, lock, wrong and right unlocks, receive, preview, download, Save to Files, restart (locked after start), unlock, disable, then an exact restore of the original `data/mca` against a sha256 manifest. The round found and fixed the points listed under Fixes. The vault is new: it has been verified on one node and in the automated tests; report anything odd.

## Fixes found while testing the vault

- **A leak in scheduled pictures (G3).** The scheduler's in-process transfer create built its multipart body with the Werkzeug test builder, which spools a body over 500 KB to a temporary file. With the vault on, a large scheduled picture (the "original" resize) would have reached the disk in plaintext. The body is now built in memory; a test with a plaintext-write spy pins it.
- **The MCAttach worker stops cleanly on shutdown.** A stop during a tick made the relay probe pool refuse new work (`cannot schedule new futures after interpreter shutdown`, logged as an ERROR). `gunicorn.conf.py`'s `worker_exit` now stops the worker first, nothing new is started once it was asked to stop, and the shutdown error ends the worker without an error line.
- After a restart and an unlock the transfer list showed "Encrypted file" for every row until each row changed; the snapshot is now rebuilt once after an unlock.
- Enable and disable wrote converted files with the umask's 0644 instead of keeping each file's own permission bits (spool files and secrets went from 0600 to 0644); they now keep them.
- A disable's backup holds the encrypted workspace; it was described as a readable plain copy. It is now listed as encrypted with a calm notice.

## Files and the interface

- **Recipient picker (UX5).** The send dialog and the scheduled picture form get a searchable list with favorites, recently used, and nodes without a key hidden behind one line ("N more nodes without a key"). The Send pictures dialog no longer shows an empty box or the upload status twice, and its status lines use the small text style. The Nodes tab empty-state message no longer shows next to results.
- **Phone layout (UX5).** The Files tab is master/detail: one view at a time, a back button, the browser and Android back work, scroll position is kept, and a deep link from a chat notification opens Details. The same layout is used on a desktop when the Files panel is narrow (both sidebars open). It works on iOS 15 (no container queries needed). On a wide screen the summary line and the filter row now fit their pane.
- **Sizes (UX5)** are written the same way everywhere (Files, Details, storage summary, send dialogs, gallery, System): B, KB, MB, GB, and Б, КБ, МБ, ГБ in Russian and Ukrainian.
- **Media gallery filter (G4)** with a live "N of M" count and **Select found**; the filter bar fits a phone; the lightbox and the toolbar summary fit a phone too; a picture whose camera name has Cyrillic letters now keeps a readable file name prefix.
- **MCAttach polish (MCA-UX2).** No accept dialog, clean previews, Files strings translated.
- **Documentation:** the vault guide, the vault design record (ADR-0013 and the proposal), README, User Guide and Docker guide.
