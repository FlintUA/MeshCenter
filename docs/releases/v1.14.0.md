# MeshCenter v1.14.0

**DRAFT release notes, written with PR 6. The owner releases; re-check the file list below at tag time.**

Range: `v1.13.11..main`. The headline is the **MCAttach vault**, an optional encryption of everything MCAttach stores on the device. It is off by default; nothing changes for an installation that does not turn it on.

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `install.sh`, `meshcenter-firstboot.sh` and the Dockerfile are unchanged since v1.13.11 (PyNaCl was already a dependency), so nothing is blocked and no manual step is needed. `gunicorn.conf.py` gains a `worker_exit` hook (a service restart picks it up, which the update does). There is **no database schema change**. Open **Workspace > System > Updates**, press **Check now**, then **Update**, and reload the page once with Ctrl+F5. **Roll back** to v1.13.11 is possible as long as the vault was never enabled; **while a vault exists Roll back is refused** ("Disable the vault first"), because older versions cannot read it. Docker users rebuild or load the image (`meshcenter:1.14.0`); the pinned ffmpeg version is 7.1.5, unchanged.

## MCAttach vault (new, optional)

- **What it encrypts:** received and queued files, their names and comments, the MCAttach identity key and the Relay upload tokens, with a passphrase only you know (Argon2id, libsodium secretstream, a recovery key). **It does not cover the Media gallery** or any other MeshCenter file.
- **Locked after every start.** While locked the Files list shows "Locked" instead of names, offers are still recorded, nothing is accepted, downloaded or decrypted, sending is refused (the Send dialog offers Unlock), and a scheduled picture send is skipped with one System Log line (the schedule stays on). A lock chip sits in the dock next to the workspace label.
- **Enable wizard** (Settings > MCAttach vault): notices, passphrase with a strength hint, a plain backup of the current data (on by default), progress, the recovery key shown once with two groups typed back, then an unlock test. A persistent, non-dismissible warning stays until the plain backup is deleted. **Disable** decrypts everything back; its backup is encrypted and is listed as such.
- **Verified on a real node** (a Raspberry Pi Zero 2 W): enable in about 4 seconds on a small workspace, lock, wrong and right unlocks, receive, preview, download, Save to Files, restart (locked after start), unlock, disable, then an exact restore of the original `data/mca` against a sha256 manifest. The round found and fixed: the list showing "Encrypted file" after a restart and unlock, converted files being written with 0644 instead of keeping their own permission bits, a disable's encrypted backup being described as a readable plain copy, and a shutdown error line from the MCAttach worker.
- **Memory:** an unlock needs the Argon2id memory limit (64 MiB on the Zero 2 W) for about a second and gives it back; measured, nothing is retained (`scripts/vault_memory_probe.py`). **Flash storage:** deleting plain files on an SD card is not a secure erase; enable the vault on a fresh installation for the strongest protection.
- **Docker:** locked after every container start; an optional, off-by-default `MESHCENTER_MCA_VAULT_UNLOCK_FILE` (a Docker secret) unlocks a NAS by itself, with the trade-off written down. See [docs/MCAttach_Vault.md](../MCAttach_Vault.md) and [ADR-0013](../architecture/ADR-0013-mca-vault.md).
- **A leak closed on the way:** the scheduler's in-process transfer create spooled a multipart body over 500 KB to a temporary file, which would have put a large scheduled picture on disk in plaintext with the vault on. The body is now built in memory.

## Files and the interface

- **Recipient picker** (send dialog, scheduled picture): a searchable list with favorites, recently used, and nodes without a key hidden behind one line; the Send pictures dialog no longer shows an empty box or the upload status twice.
- **Phone layout:** the Files tab is master/detail (one view at a time, a back button, the browser back works, a deep link from a chat notification opens Details). The same layout is used on a desktop when the Files panel is narrow (both sidebars open). It works on iOS 15 (no container queries needed).
- **Sizes** are written the same way everywhere, with localized units (B, KB, MB, GB; Russian and Ukrainian: Б, КБ, МБ, ГБ).
- **Media gallery filter** with a live "N of M" count, "Select found", and a Cyrillic file name fallback for the picture prefix.
- **Nodes tab:** the empty-state message no longer shows next to results.
- MCAttach: no accept dialog, clean previews, Files strings translated (MCA-UX2).

## Known issues

Unchanged from v1.13.5 (see its notes). The vault is new: it has been verified on one Zero 2 W and in the automated tests; report anything odd.
