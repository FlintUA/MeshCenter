# MeshCenter v1.15.0

Range: `v1.14.0..main` (PRs #458 to #460). One theme, **a simpler Files tab**, in three steps: a new one-column Files list (A), a new way files are received and stored plus any file type (B), and passive marking of nodes that run MeshCenter (C).

`requirements.txt`, `adapters/meshtastic/requirements.txt`, the systemd unit, the sudoers templates, the udev rule, the privileged helper scripts, `install.sh`, `meshcenter-firstboot.sh`, the Dockerfile and `gunicorn.conf.py` are unchanged since v1.14.0, so nothing is blocked and no manual step is needed. There is **one database schema change** (the MCAttach database goes from version 18 to 19, see "Update and roll back"). Open **Workspace > System > Updates**, press **Check now**, then **Update**, and reload the page once with Ctrl+F5.

Docker users rebuild or load the image (`meshcenter:1.15.0`); the pinned ffmpeg version of this release is 7.1.5, unchanged.

## Please note before you update

- **Auto-accept is on by default.** A file offered by a contact whose key you trust is now downloaded without a tap, up to 50 MB or 20 files per contact in 24 hours. Above that the offer waits for your Download and the card says why. Switch it off in **Settings > Files / MCAttach** ("Accept files from trusted contacts automatically").
- **The first start after the update moves files.** Received files that were still in the internal cache are moved into the Files folder once (details below). The Files folder now holds every received file.
- **The sender's own copy of a finished transfer is deleted** (after Delivered, Expired, Cancelled, Revoked or Rejected). The history entry stays. A transfer that failed keeps its copy, so Retry still works.
- **Any file type can be sent**, with the safety rules unchanged in spirit (below). A node that still runs an older version cannot SEND types its own allowlist refuses; it can still RECEIVE them.

## Files: one column of cards (Phase A)

- **One list on every width**, no separate Details pane. Segments **Incoming / Sent / All** with counters (remembered per device). Each entry is a card: thumbnail or type icon, name, size, time, the comment, **one plain status** ("Received", "Waiting for recipient", "Delivered", "Not delivered: the link expired", and so on) and the actions (Open, Download to device, Delete; Retry and Cancel while sending). Direction is a coloured stripe **and** words ("Received from X", "Sent to X"). "Link valid for N more days" shows while a file waits; the technical rows are under "More details".
- **Date groups** (Today, Yesterday, dates), a messenger layout when one contact is selected, **multi-select** (checkboxes, long press on a phone) with bulk Download and Delete, an executable-download warning, and a "Files use X, Clean up..." line.
- **Phones:** one 44 px toolbar (segments, search, more menu), a floating **+** to send, compact cards (about 58 px, a tap opens the actions), short status words on narrow screens, and the list uses all the height that is left. Checked from 320 px.
- **Incoming thumbnails** are made on the node from the verified file (size capped, never stored, under the vault never cached).
- **Send dialog:** a favorites star in the search row, expiry presets **1 h, 6 h, 1 d, 3 d, 7 d, 14 d (default), 30 d** inside what the relay allows (a relay that keeps files less than 14 days has its maximum as the default and the dialog says so), "Custom" as a number and a unit with one range message, and a comment with a remaining-characters count near the limit.
- **Relay limits** (maximum size and TTL, minimum TTL when published) are refreshed on **every provider check**, so a change on the relay reaches the send dialog without editing the node. Your own limit, if you set one, is kept **separately** and the stricter of the two applies; a refresh never overwrites yours. Relay providers are in Settings only.
- **Node card:** one "Request key" button.

## Files: how received files are stored and handled (Phase B)

- **One store.** A received file is written straight into the Files folder (with the vault on, as an encrypted `<id>.mcv` file). Before, it waited in a cache until "Save to Files". Files that are still in the cache at the update are **moved once, atomically, one at a time, through a journal** (`storage_merge.journal` in the MCAttach folder), so an interrupted move (power loss) resumes with the same names. Nothing is copied, decrypted or overwritten; a name that is taken becomes `Name (2).pdf`. Verified on a copy of real node data and on a real node.
- **Auto-accept** (see above) with the per-contact quota in a rolling 24 hours. The size is checked from the relay's descriptor **before** any part of the file is fetched.
- **The comment now travels both ways:** the sender keeps it on the sent entry, the receiver stores the sender's comment (sealed under the vault) and shows it on the card.
- **Sender copy deletion** as described above; only the file goes, never the entry.
- **Any file type.** The sender no longer refuses a type. What stays: the type is derived from the file **content** (anything unknown is `application/octet-stream`), the name is kept and sanitized to a single component, only a verified JPEG, PNG or WebP is ever shown inline, everything else (HTML, SVG, PDF, scripts, archives) is a download with `nosniff` and a sandbox, nothing is executed or unpacked, an executable asks before it is downloaded, and a file declared or detected as an image must really be that image or it is refused on receive. An empty file is the only thing refused.
- **Automatic cleanup** of old received files: **off by default**; in Settings you can choose 30, 60, 90 or 180 days (it asks once, then runs about hourly, entries stay in the history). The manual **Clean up** now covers every received file.
- **Sorting:** newest first by default everywhere (also in a contact's conversation), or oldest first, name, size; remembered separately for a desktop and a phone. Date groups follow the order and disappear for name and size.
- **A contact filter chip:** when you select a contact in the sidebar, the list shows "Only: <contact> x" above it (x shows all files again) and the counters say they are for that contact. Before, the narrowing was invisible.

## Nodes: passive MeshCenter marking (Phase C)

- A node is marked as running MeshCenter when this node **receives a real MeshCenter control frame from it** (a file offer, a key request or announce, an acknowledgement). **Nothing is ever sent for it**: no broadcast, probe or beacon.
- The node list shows an **MC** badge (tooltip with first and last seen; the selected card shows a row), a **MeshCenter only** filter in Sort and filters, and an **MC n** counter in the Nodes header (it toggles the same filter). The recipient picker shows the MC mark and has a "MeshCenter only" toggle.
- **Back-fill at start:** every node with a key binding in any trust state, a received file offer or a received acknowledgement is marked from MCAttach's own records, so known MeshCenter nodes show the badge right after the update.
- **It is advisory, not trust.** The frame is checked for its shape only; anyone who knows the format could look like MeshCenter. Trust is still only the key exchange.

## Update and roll back

- **Database 18 to 19.** The MCAttach database gets six columns that keep a provider's relay limits and your own limits apart. Existing providers keep their stored values as the relay values and have no limit of your own (a value saved at registration cannot be told from a deliberate one; if you had lowered a limit on purpose, set it again).
- **Rolling back to v1.14.0 works.** v1.14.0 opens a version 19 database as it is (the extra columns are ignored) and treats files in the Files folder as saved files. What a rollback does not undo: the moved files stay in the Files folder, the deleted sender copies are gone, and the new Files settings are ignored. Roll back from **Workspace > System > Updates** as usual; **while a vault exists, Roll back is still refused** ("Disable the vault first").
- Docker: a volume that was used by v1.15.0 can be used by an older image for the same reasons.

## Known issues

Unchanged from v1.13.5 (see its notes). The Files tab was checked on iPhone SE, Android and desktop in light and dark. If a file seems to be missing after the update, look in the Files folder: received files from the old cache are there now.
