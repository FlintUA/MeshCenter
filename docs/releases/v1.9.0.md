# v1.9.0 — release notes (awaiting OK before tagging)

Range: `v1.8.4..main` (`d7b6fca`), PRs #311–#329.

## Security

- Password change or disabling authentication now requires the current password, checked against the same login-throttle backoff as `/login`; sessions are invalidated on a password change or when protection is disabled (new `auth_version`, #321)
- `meshtastic` CLI's `--info` output is now parsed as real JSON instead of brace-counting — fixes a neighbor node's telemetry/metrics leaking into the local node's own readings, and a node whose name happened to contain `{`/`}` silently blocking import of every other node in the same dump (#318)
- `requests` floor raised to `>=2.32.4` — closes a gap where 2.31.0–2.32.1 could silently fall back to an *unpinned* HTTPS connection in the Relay client, plus picks up CVE-2024-35195 and CVE-2024-47081 (#321)
- XSS: `escapeHtml()`/`escapeJsString()` made context-correct instead of only escaping `& < >` (#311)
- NaN/Infinity values from a malformed packet are now sanitized to `None` instead of crashing every subsequent call to `/api/nodes_export` (#322)
- CSV node export/import rewritten to real RFC-4180 (was only escaping one of eight columns) with a formula-injection guard (#323)
- Settings validation now rejects NaN/Infinity on numeric fields that previously let them through silently (#313)

## Storage reliability

- Atomic JSON writes rewritten: each write now stages to a unique temp file (the old shared fixed `<file>.tmp` name let a concurrent read delete an in-flight writer's own temp file); a corrupt file is now quarantined to `<file>.corrupt-<timestamp>` instead of being silently overwritten by defaults (#319)
- Every mutating HTTP route that saves state now actually reports a failed write (`storage_write_failed`, HTTP 500) instead of answering `ok: true` regardless; affected in-memory state is rolled back to match disk (#320)
- Fixed `ensure_chat()` crashing with `AttributeError` on every inbound TCP position/text event for a radio profile whose `deleted_dm.json` was created in the wrong shape — live on pixel-111, confirmed fixed under 31 minutes of real traffic with zero further errors (#327)
- Same latent shape mismatch fixed for `telemetry_history.json` before it could cause a live failure (#328)
- `messages`/`chats` are now mutated in place instead of being rebound, so modules that captured a reference at startup (`api/api_chat.py`) never silently diverge from `server.py`'s own view of the same list (#312)

## Radio & transports

- TCP identity probing (Discovery/Accept/profile-activate) now runs through its own, separate adapter process instead of sharing the production session's — a hung or failed probe can no longer kill or corrupt an already-connected production radio link (#317)
- `seen_ids` dedup replaced with an insertion-ordered container with both a count and an age cap, so cleanup can no longer discard recently-seen packet IDs depending on set iteration order (#323)
- Radio health's "packet received" signal now fires only for a recognized packet line, not for every line the CLI prints — separated from a new `last_cli_activity` signal that still tracks raw CLI output (#323)

## Camera

- USB cameras (`camera/usb_driver.py`) now drive `ffmpeg`/`v4l2-ctl` as external subprocesses instead of importing `linuxpy`/`v4l2py` (GPL-3.0-or-later) directly into Core's process — same arm's-length approach already used for the Meshtastic CLI (#314)
- Fixed a subprocess-spawning bug (`PR_SET_PDEATHSIG` is per-thread, not per-process) that could leave an orphaned `ffmpeg` process running after a crash under Werkzeug's dev server; the fix was generalized into one shared spawner used everywhere in the codebase that arms this signal, including the radio adapter's own respawn path (#314, #315)

## Telemetry

- The "History recording" toggle now actually does something — previously written but never read, so disabling it had zero effect. Live values keep updating regardless; only history writes stop (#322)
- The 30-day telemetry chart is no longer capped at 5000 records shared across every node — server-side downsampling by time range, with a 10,000-record cap applied independently per node instead of one shared ceiling a single chatty remote node could exhaust (#322)
- Telemetry history saves are now debounced (at most once every 60 seconds while dirty) instead of rewriting the entire history file on every single accepted record — measured at 3.53s per write on a real 24,000-record history on a Pi Zero 2W before this fix (#324)

## Docs & CI

- README restructured from ~1950 to ~340 lines, with details moved to `docs/User_Guide.md`, `docs/architecture/Architecture.md`, and `docs/BACKEND_API.md`; corrected several stale/false claims, most importantly a Security section that claimed "no built-in user authentication" (#326)
- New auto-generated `docs/API_ROUTES.md` (167 routes) plus two new CI checks: one fails if the route inventory goes stale or a doc references a nonexistent `/api/` path, the other validates every relative link and heading anchor across the actively-maintained docs (#326)
- License notices completed for Chart.js/@kurkle/color (full MIT text, not just a one-line pointer); GPLv3 scope of the adapter process clarified (#325)
- A test now enforces that `storage/profile_manager.py`'s default telemetry config stays in sync with `telemetry/telemetry.py`'s own default, rather than relying on a comment (#329)

## Upgrade notes

- **USB cameras now need `ffmpeg` and `v4l-utils`** (apt packages, not Python): `sudo apt install -y ffmpeg v4l-utils`. An existing install's venv should also drop the now-unused GPL dependency: `source venv/bin/activate && pip uninstall -y v4l2py linuxpy && deactivate` (`pip install -r requirements.txt` alone won't remove a package that's no longer listed).
- **`requests` floor raised to `>=2.32.4`** — re-run `pip install -r requirements.txt` in Core's venv to pick it up; no code changes needed on your end.
- **Changing your password or disabling authentication now asks for your current password first**, and does so under the same throttling as a failed login.
- **Telemetry history is now capped at 10,000 records per node** (independently, not shared) and flushed to disk at most once every 60 seconds instead of on every record — a clean shutdown/restart flushes immediately; an unclean crash can lose up to ~60 seconds of telemetry *history* (live current-value readings are unaffected).
- **A corrupt JSON data file is now quarantined** (renamed to `<file>.corrupt-<timestamp>`, up to 3 kept) instead of being silently replaced and overwritten — if you ever see one of these appear under `data/`, it's worth a look rather than deleting it outright.

## Known limitations

- USB MJPEG passthrough is implemented and unit-tested, but has not been live-verified against a real MJPEG-capable USB camera (the reference hardware used in testing is YUYV-only).
- Bluetooth (BLE) is send-only — MeshCenter cannot receive anything (messages, telemetry, NodeInfo) while BLE is the active transport.
- TCP has a narrower receive scope than serial: no routing ACKs, no remote waypoint deletion, and an event captured while the link is down (or buffered in an adapter process killed before the next drain) can be lost.
- The README's screenshots are from v1.5.0 and don't reflect the current four-tab-plus-Files layout; refreshing them is tracked as a follow-up.
