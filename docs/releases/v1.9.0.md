# MeshCenter v1.9.0

Range: `v1.8.4..main` (`d7b6fca`), PRs #269–#329 (skipping #268, a docs-only version-history bump, and #309, temporary debug logging never meant to ship).

## Security

- Replaced the auto-generated first-run password (written to a file on disk, found by reading a log line) with a mandatory in-browser `/setup` wizard — no password is ever generated, logged, or written to disk in plaintext (#273)
- Changing your password, or disabling authentication once a password is set, now requires your current password (checked under the same login-throttle backoff as `/login`). Sessions are invalidated on a password change or when re-enabling previously-disabled protection — **not** on disabling itself — and the session making the change always stays logged in (new `auth_version`, #321)
- The Relay client's SSRF defenses now explicitly reject multicast, unspecified, reserved, link-local, loopback and private addresses as destinations, closing a gap where `ipaddress`'s `.is_global` alone treated multicast as an acceptable "global" target (#321)
- `/api/nodes_import` now validates every field instead of trusting the request body outright: node IDs checked, a 2000-entry cap, name/short-name length limits, non-finite RSSI/SNR rejected, and out-of-range positions dropped rather than erasing a previously-good one (#321)
- `requests` floor raised to `>=2.32.4` — the old `>=2.31.0` floor allowed a version where the Relay client's IP-pinning silently fell back to an *unpinned* connection with no error; also picks up CVE-2024-35195 and CVE-2024-47081 (#321)
- `meshtastic` CLI's `--info` output is now parsed as real JSON instead of brace-counting — fixes a neighbor node's telemetry/metrics leaking into the local node's own readings, and a node whose name happened to contain `{`/`}` silently blocking import of every other node in the same dump (#318)
- XSS: `escapeHtml()`/`escapeJsString()` made context-correct instead of only escaping `& < >` (#311)
- NaN/Infinity values from a malformed packet are now sanitized to `None` instead of crashing every subsequent call to `/api/nodes_export` (#322)
- CSV node export/import rewritten to real RFC-4180 (was only escaping one of eight columns) with a formula-injection guard (#323)
- Settings validation now rejects NaN/Infinity on numeric fields that previously let them through silently (#313)

## Storage reliability

- Atomic JSON writes rewritten: each write now stages to a unique temp file (the old shared fixed `<file>.tmp` name let a concurrent read delete an in-flight writer's own temp file); a corrupt file is now quarantined to `<file>.corrupt-<timestamp>` instead of being silently overwritten by defaults (#319)
- Every mutating HTTP route that saves state now actually reports a failed write (`storage_write_failed`, HTTP 500) instead of answering `ok: true` regardless; affected in-memory state is rolled back to match disk (#320)
- Deleting all DM chats now reports success with a warning (instead of a misleading 500) if only the "deleted" marker file fails to write after the chats themselves were already removed — the deletion already happened, so the response says so (#323)
- Fixed `ensure_chat()` crashing with `AttributeError` on every inbound TCP position/text event for a radio profile whose `deleted_dm.json` was created in the wrong shape — verified under live TCP traffic with zero further errors (#327)
- Same latent shape mismatch fixed for `telemetry_history.json` before it could cause a live failure (#328)
- `messages`/`chats` are now mutated in place instead of being rebound, so modules that captured a reference at startup (`api/api_chat.py`) never silently diverge from `server.py`'s own view of the same list (#312)

## Radio & transports

- New TCP transport: connect to a Meshtastic radio over its native TCP protocol (default port 4403) as a third option alongside USB serial and Bluetooth, with its own explicit connection-state machine (#277, #278)
- Two stability bugs fixed shortly after the TCP transport's introduction: a leaked reader thread after a failed connection attempt could silently block every subsequent TCP connect through the same adapter process until it was killed and respawned (#279), and a raw protobuf object leaking into a NodeInfo's position field could crash the whole adapter subprocess (#280)
- TCP can now receive inbound data over the mesh, not just send: text messages and waypoints first (#300–#303), then NodeInfo, position and telemetry (#305–#308) — all routed through the same shared ingest path serial already used, so chat routing, dedup and waypoint behavior are identical regardless of which transport delivered them
- A radio reachable over more than one link (e.g. USB and Wi-Fi) now remembers all of them instead of only the most recently used one; Node Manager gained an "Available connections" list (Use/Edit/Remove) and a transport-aware discovery dialog, replacing the old USB-only "Detect radio" flow (#281–#285)
- The System page's Radio Status widget and the background health-check worker now report real status for TCP/Bluetooth radios instead of defaulting to serial-only assumptions (stuck on "STARTING" forever, or a connected radio falsely shown as "Listener stopped"/"Offline") (#286, #292, #295)
- TCP/Bluetooth radios now auto-reconnect after a sustained disconnect or error, survive a transient boot-race identity-check failure, and retry identity verification in the background instead of staying blocked until a manual reconnect or service restart (#287–#289, #293, #294)
- A string of TCP connection-lifecycle bugs found and fixed through live testing with a TCP-connected radio: a non-idempotent `connect()` that could open duplicate sessions, a reconnect that silently failed after an adapter respawn, a stale session left open after a failed identity check, a reconnect timeout that reset on every retry instead of counting down from one budget, and a probe socket reused incorrectly (#290, #296–#299, #304)
- TCP identity probing (Discovery/Accept/profile-activate) now runs through its own, separate adapter process instead of sharing the production session's — a hung or failed probe can no longer kill or corrupt an already-connected production radio link (#317)
- `seen_ids` dedup replaced with an insertion-ordered container with both a count and an age cap, so cleanup can no longer discard recently-seen packet IDs depending on set iteration order (#323)
- Radio health's "packet received" signal now fires only for a recognized packet line, not for every line the CLI prints — separated from a new `last_cli_activity` signal that still tracks raw CLI output (#323)

## Messaging

- `reply_id` is now independent protocol metadata instead of being derived, fixing a case where a reply could silently lose its reply reference (#310)
- Sidebar node card: selecting a node updates its detail content immediately instead of waiting up to several seconds for the next poll tick (#271); a collapsed card now always shows the node's role, not only when it's selected (#272)
- Fixed a bug where a failed initial channel-list refresh could retry in a loop roughly every 10 seconds indefinitely, repeatedly stopping and restarting the radio listener until the browser tab was closed (#270)

## MCAttach

- Files (MCAttach) node card: word-wrapped message previews instead of ellipsis truncation, separate "Last sent"/"Last received" rows naming the actual file, and a collapsible node-detail body (#269)

## Camera

- USB cameras (`camera/usb_driver.py`) now drive `ffmpeg`/`v4l2-ctl` as external subprocesses instead of importing `linuxpy`/`v4l2py` (GPL-3.0-or-later) directly into Core's process — same arm's-length approach already used for the Meshtastic CLI (#314)
- Fixed a subprocess-spawning bug (`PR_SET_PDEATHSIG` is per-thread, not per-process) that could leave an orphaned `ffmpeg` process running after a crash under Werkzeug's dev server; the fix was generalized into one shared spawner used everywhere in the codebase that arms this signal, including the radio adapter's own respawn path (#314, #315)

## Telemetry

- The "History recording" toggle now actually does something — previously written but never read, so disabling it had zero effect. Live values keep updating regardless; only history writes stop (#322)
- The 30-day telemetry chart is no longer capped at 5000 records shared across every node — server-side downsampling by time range instead. History itself now has real per-scope caps: 10,000 records for the local radio, 1,000 per remote node, and a 40,000-record ceiling across the whole mesh (oldest *remote* records evicted first when that ceiling is hit; local history is never evicted by remote traffic) (#322)
- Telemetry history saves are now debounced (at most once every 60 seconds while dirty) instead of rewriting the entire history file on every single accepted record — measured at 3.53s per write on a real 24,000-record history on a Pi Zero 2W before this fix — and written as compact JSON, ~30% smaller on disk than the old pretty-printed format (#324)

## Docs & CI

- Read-only architecture audit (server.py decomposition, dependency map, storage inventory, Docker/GPL blockers) laying groundwork for future containerization work — no code changed (#276)
- README install instructions clarified: the install progress page is on port 80, not 5000, during setup; the `.local` address used to reach a fresh install depends on the hostname set in Raspberry Pi Imager (#274, #275)
- README restructured from ~1950 to ~340 lines, with details moved to `docs/User_Guide.md`, `docs/architecture/Architecture.md`, and `docs/BACKEND_API.md`; corrected several stale/false claims, most importantly a Security section that claimed "no built-in user authentication" (#326)
- New auto-generated `docs/API_ROUTES.md` (167 routes) plus two new CI checks: one fails if the route inventory goes stale or a doc references a nonexistent `/api/` path, the other validates every relative link and heading anchor across the actively-maintained docs (#326)
- License notices completed for Chart.js/@kurkle/color (full MIT text, not just a one-line pointer); GPLv3 scope of the adapter process clarified; the GPLv3 license-boundary check moved to a dedicated, reusable script (`scripts/check_core_gpl_imports.py`) and extended to also catch `linuxpy`/`v4l2py` imports or requirements-file entries in Core, not just `meshtastic` (#325)
- A test now enforces that `storage/profile_manager.py`'s default telemetry config stays in sync with `telemetry/telemetry.py`'s own default, rather than relying on a comment (#329)

## Upgrade notes

- **If you already have a password set (any install that's been through first-run before), nothing changes on login.** The old auto-generated-password mechanism (#273) wrote a real password hash to `data/auth.json`; that file's existing `password_hash` is read exactly as before, so your current password keeps working and you will **not** see the new `/setup` wizard. `/setup` only appears for a genuinely fresh install with no `auth.json` yet, or one where the password was somehow cleared.
- **The multi-connection model (#281) needs no manual migration step.** Your existing `instance.json` radio record is read as before; the new `connections`/`preferred_transport` fields are synthesized automatically from your existing transport/endpoint the first time it's read, and the legacy fields are always kept alongside them unchanged — no new files appear under `data/`, and nothing is deleted or restructured. Downgrading to v1.8.4 afterwards should be safe for the same reason (older code simply ignores the extra field), but as with any upgrade spanning this many releases, back up `data/` first as a matter of course.
- **The adapter venv (`adapters/meshtastic/venv`) needs no changes** — `adapters/meshtastic/requirements.txt` is unchanged since v1.8.4.
- **USB cameras now need `ffmpeg` and `v4l-utils`** (apt packages, not Python): `sudo apt install -y ffmpeg v4l-utils`. Your existing Core venv should also drop the now-unused GPL dependency: `source venv/bin/activate && pip uninstall -y v4l2py linuxpy && deactivate` (`pip install -r requirements.txt` alone won't remove a package that's no longer listed).
- **`requests` floor raised to `>=2.32.4`** — picked up automatically the next time you run `pip install -r requirements.txt` in Core's venv; no action needed beyond the standard update steps below.
- **Changing your password, or disabling authentication, now asks for your current password first**, under the same throttling as a failed login attempt.
- **Telemetry history now enforces real caps** (10,000 local / 1,000 per remote node / 40,000 total — see Telemetry above) and flushes to disk at most once every 60 seconds instead of on every record. A clean shutdown/restart flushes immediately; an unclean crash can lose up to ~60 seconds of telemetry *history* (live current-value readings are unaffected).
- **Installs that went through first run on v1.8.x may still have `data/initial_password.txt`**, a plaintext copy of the auto-generated password. v1.9.0 no longer creates it, but doesn't remove an existing one. If you never changed that password, change it in Settings → Security now, then delete the file: `rm data/initial_password.txt`.
- **A corrupt JSON data file is now quarantined** (renamed to `<file>.corrupt-<timestamp>`, up to 3 kept) instead of being silently replaced and overwritten — if one appears under `data/`, it's worth a look rather than deleting it outright.
- **This release changes `requirements.txt`, so the Updates card will show manual instructions instead of applying it.** Upgrade from the command line: back up `data/` and `config.py` → `git fetch --tags && git merge --ff-only origin/main` (or check out `v1.9.0`) → `source venv/bin/activate && pip install -r requirements.txt && pip uninstall -y v4l2py linuxpy` → `sudo apt install -y ffmpeg v4l-utils` → `sudo systemctl restart meshcenter.service`. The adapter venv needs no changes this release. See `docs/User_Guide.md`'s "Update MeshCenter safely" section for the full procedure.

## Known limitations

- USB MJPEG passthrough is implemented and unit-tested, but has not been live-verified against a real MJPEG-capable USB camera (the reference hardware used in testing is YUYV-only).
- Bluetooth (BLE) is send-only — MeshCenter cannot receive anything (messages, telemetry, NodeInfo) while BLE is the active transport.
- TCP has a narrower receive scope than serial: no routing ACKs, no remote waypoint deletion, and an event captured while the link is down (or buffered in an adapter process killed before the next drain) can be lost.
- Not yet verified on a RAK4631 over USB serial in this release cycle.
- No hot-reconnect after a physical serial cable unplug/replug — recovery still needs a full service restart, not just a Settings click. Planned for the next release.
- The README's screenshots are from v1.5.0 and don't reflect the current four-tab-plus-Files layout; refreshing them is tracked as a follow-up.
